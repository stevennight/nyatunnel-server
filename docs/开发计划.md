# 开发计划

背景与整体设计见 [设计方案](设计方案.md)，接口见 [协议](协议.md)。

## 已定决策（2026-10-03 / 04）

- 数据面自研：WebSocket（经 Caddy 443）+ yamux，不内嵌 frp；可选直连 TLS 端口（证书指纹钉住）
- 协议实现放在公共库 `nyatunnel-common`，服务端与客户端共用
- 客户端：Go 核心 + CLI，GUI 用 Tauri 2 + React；全平台，Windows 优先
- 账号：管理员 + 普通用户，均支持 TOTP；普通用户默认一切需审批，可按用户开自助额度
- 部署：在已有 Caddy 之后运行；证书全部由 Caddy 管理（Cloudflare DNS-01 通配 + on-demand 自定义域名）
- 域名不写死：后台可配置多个隧道根域名和自定义域名
- 三个仓库均公开

## v0.1.4

- [x] 客户端无人值守更新：Windows 桌面版由独立的更新程序静默安装并自动重启，新版本没有启动或没能重新连上服务器时恢复旧版本；Windows 系统服务（SYSTEM，无 UAC）自动检查、更新并在失败时回滚，服务程序迁到仅管理员可写的 `%ProgramData%\NyaTunnel\bin`

## v0.1.5（客户端）/ v0.1.4（服务端）

- [x] 设备端确认（协议 §4.6）：下发的隧道要设备主人在本机确认后才接通，确认绑定隧道类型与本地目标，管理员改动后需重新确认；服务端被攻破时也不能借设备暴露未经同意的地址。客户端桌面端在隧道列表确认，命令行 `nyatunnel tunnels confirm`；管理台显示“等待设备确认”，访客看到对应提示页
- [x] 客户端本地状态改存 SQLite（`nyatunnel.db`）：设备身份、直连端点、确认记录、最近一次配置；旧的 `identity.json` / `direct.json` 首次启动自动导入，升级前已在运行的隧道视为已确认
