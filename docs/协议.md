# NyaTunnel 通信协议

> 状态：**协议 1.0**（2026-10-04）。同一主版本内只增不改，新行为通过能力协商（`features`）或可选字段开启，而不是比较版本号。

服务端与客户端通过本文档对接。握手、帧格式、流头的 Go 实现在公共库 [`github.com/stevennight/nyatunnel-common/tunnelproto`](https://github.com/stevennight/nyatunnel-common)，两端都依赖它；深链与注册码在同库的 `deeplink`。设计背景见 [设计方案 §5–§9](设计方案.md#5-设备身份)。

## 1. 约定

- 所有接口走 HTTPS，前缀 `/api/v1`，JSON（UTF-8）。服务端地址即 `NYATUNNEL_PUBLIC_URL`。
- 错误响应：`{"error": "<code>", "message": "<人类可读>"}`。
- WebSocket 关闭码：
  - `4401` 设备不存在 / 已吊销 / 归属用户已禁用 / 签名错误 —— 客户端应清除本地凭据；
  - `4409` 同一设备的新会话顶替了本会话 —— 不要立即重连抢回；
  - `4426` 客户端版本低于 `minClientVersion`；
  - 其他关闭、断网、5xx：保留凭据，指数退避重连（1s 起，上限 60s，加随机抖动）。

## 2. 深链

| 链接 | 说明 |
|---|---|
| `nyatunnel://enroll?v=1&s=<host[:port]>&c=<code>` | 注册设备 |
| `nyatunnel://open?s=<host[:port]>&t=<tunnel_id>` | 打开客户端并定位隧道 |

客户端收到深链时永远不直接改变状态，必须由用户确认。参数缺失、重复、多余、版本未知一律拒绝。

## 3. 设备注册（REST）

### `GET /api/v1/enroll/preview?code=<code>`

不消耗注册码。

```json
{ "serverName": "Nya 的家庭网络", "owner": "alice", "deviceNameHint": "dev-laptop",
  "tunnels": [{ "name": "demo-share", "publicUrl": "https://alice-demo.dev.example.com" }],
  "expiresAt": "2026-10-03T12:10:00Z" }
```

错误：`enrollment_invalid`（不存在 / 已使用 / 已过期，不区分）、`rate_limited`。

### `POST /api/v1/enroll/claim`

```json
{ "code": "K7QP-3XMD", "publicKey": "<base64 Ed25519>", "deviceName": "dev-laptop",
  "platform": "windows/amd64", "clientVersion": "0.1.0", "gui": true }
```

响应 `{ "deviceId": "dev_…" }`。设备归属于生成该注册码的用户。

## 4. 设备连接 `GET /api/v1/device/connect`（WebSocket）

整个设备生命周期只有这一条连接：先握手认证，再在其上运行 yamux。

### 4.1 握手（WebSocket 文本帧，JSON）

| 顺序 | 方向 | 消息 |
|---|---|---|
| 1 | C→S | `{"type":"hello","deviceId":"dev_…","protocol":"1.0","clientVersion":"0.1.0","features":[…]}` |
| 2 | S→C | `{"type":"challenge","nonce":"<base64 32B>"}` |
| 3 | C→S | `{"type":"auth","signature":"<base64>"}`，签名内容：`"nyatunnel-connect-v1\n" + host + "\n" + deviceId + "\n" + nonce` |
| 4 | S→C | `{"type":"welcome","sessionId":"…","protocol":"1.0","features":[…]}` 或以 `4401` 关闭 |

`host` 为客户端连接时使用的服务器主机名（小写，不含默认端口 443）。握手须在 10 秒内完成。

能力（`features`）：

| 名称 | 方向 | 含义 |
|---|---|---|
| `gui` | C→S | 客户端带图形界面（仅用于展示） |
| `probe` | C→S | 只读查询会话（`nyatunnel status`）：服务端推送一次配置，不顶替设备正在运行的会话，也不向它路由流量 |

### 4.2 多路复用

`welcome` 之后，WebSocket 二进制帧承载 yamux 字节流（客户端为 yamux client，服务端为 server）。

- **控制流**：客户端打开的第一条流。消息为换行分隔的 JSON（`{type, id?, data}`），单条不超过 1 MiB。
- **数据流**：由服务端为每个访客连接打开。流开头是流头（§4.4），其后为原始字节。

### 4.3 控制流消息

| 方向 | type | data |
|---|---|---|
| S→C | `config` | 完整配置快照（§5），每次变更推送一次 |
| S→C | `notice` | `{level, text}` |
| C→S | `status` | `{tunnelId, state: "running"\|"paused"\|"error", error?}` |
| C→S | `stats` | `{tunnelId, bytesIn, bytesOut, conns}`，每 60 秒 |
| C→S | `tunnel.update` | `{tunnelId, localIp?, localPort?, pausedByClient?}`，仅允许 `permissions` 放行的字段 |
| C→S | `request.create` | `{type, subdomain, localIp, localPort, duration: "24h"\|"7d"\|"30d"\|"", reason}`，服务端建立一条待审批的隧道申请并通知管理员 |
| S→C | `result` | `{id, ok, error?}`，对带 `id` 的请求的应答 |
| 双向 | `ping` / `pong` | `{}`，30 秒一次，90 秒无响应视为断线 |

越权的 `tunnel.update` 返回 `{ok:false, error:"field_not_allowed"}` 并记审计日志。

### 4.4 数据流

服务端打开流后先写流头：长度前缀（2 字节大端，≤ 4096）+ JSON：

```json
{ "tunnelId": "tun_…", "proto": "tcp", "remoteAddr": "203.0.113.4:51234" }
```

客户端读完流头、尝试连接本地目标后，回 **1 字节应答**，之后才是双向载荷：

| 值 | 含义 | 服务端对 HTTPS 访客的表现 |
|---|---|---|
| 0 | 成功 | 正常转发 |
| 1 | 快照中没有这个隧道 | 503 隧道已暂停 |
| 2 | 隧道在设备上未启用（暂停 / 停用 / 过期） | 503 隧道已暂停 |
| 3 | 本地服务连接失败 | 502 本地服务不可达 |
| 4 | 本地目标违反权限（如“仅回环地址”） | 502 |

- 流头不携带本地目标地址：客户端根据当前快照中的 `tunnelId` 查本地地址，服务端无法借此让设备连接任意地址。
- 隧道类型 `type`：`https`、`tcp`、`udp`、`tcpudp`（同一公网端口同时转发 TCP 与 UDP）。`tcpudp` 隧道的每条流按访客实际协议写 `proto`，设备用同一本地端口按该协议连接。
- HTTPS 与 TCP 隧道的 `proto` 都是 `tcp`；`udp` 时每个数据报前加 2 字节大端长度，单个数据报 ≤ 65535 字节，同一访客地址复用一条流，60 秒无数据回收。
- 任一方向结束写入时半关闭流（yamux FIN），另一方向可继续传完。

## 5. 配置快照

```json
{
  "rev": 42,
  "tunnels": [{
    "id": "tun_…", "name": "demo-share", "type": "https",
    "publicUrl": "https://alice-demo.dev.example.com",
    "localIp": "127.0.0.1", "localPort": 3000,
    "enabled": true, "pausedByClient": false, "expiresAt": "2026-10-03T15:00:00Z",
    "permissions": { "editLocal": true, "loopbackOnly": false, "toggle": true },
    "display": { "accessPolicy": "password", "limits": "20 Mbps · 200 连接" }
  }],
  "canRequest": true,
  "minClientVersion": "0.1.0",
  "direct": { "addr": "tunnel.example.com:7443", "certSha256": "ed6323…06b0" }
}
```

- `display.accessPolicy` 为 `public` / `password` / `basic` / `login`，`display.limits` 是给界面看的限制摘要。
- `canRequest`：设备可以通过 `request.create` 提交隧道申请。
- `minClientVersion`：低于此版本的客户端在握手后会被以 `4426` 关闭，界面应提示升级。版本比较只看 `MAJOR.MINOR.PATCH`，忽略 `-` 后缀。
- `direct`：见 §4.5；未启用直连时省略。

### 4.5 直连传输（可选）

服务端设置 `NYATUNNEL_DIRECT_LISTEN` 后，在独立端口上用 **自签名证书** 提供同样的 `GET /api/v1/device/connect`（TLS 1.3），并在每份配置快照里通过 `direct` 下发地址与证书的 SHA-256 指纹（十六进制，DER 编码证书）。

- 指纹只经由已认证的会话（经公网证书校验的 443）下发，客户端保存在身份目录的 `direct.json`。
- 客户端下次连接时先拨直连地址，只接受指纹完全一致的证书（不校验主机名与签发者）；5 秒内失败则改走公网地址，并在 10 分钟内不再尝试直连。
- 握手、签名内容与 443 完全相同（签名里的 `host` 仍是公网主机名）。
- 配置里不再出现 `direct` 时客户端删除保存的端点。

## 6. Caddy 询问接口（仅内部监听器）

`GET http://127.0.0.1:8082/caddy/ask?domain=<host>`：域名是“已生效”的根域名子域或自定义域名时返回 `200`，否则 `404`。不经过任何反代。
